# Project language

Use English as the primary language for all new or substantially revised project writing: documentation, reports, experiment records, website content, code comments, commit messages, GitHub Issues, and pull requests. Keep terminology consistent with the existing APIs and research records.

Preserve literal benchmark and test inputs, expected outputs, protocol fields, identifiers, commands, paths, hashes, model revisions, numerical results, and raw evidence. These may contain other languages when required by the test or historical record. Translate explanatory prose without changing the underlying evidence or the meaning of unsuccessful results.

Follow the repository's experiment and deployment SOPs. Submit project changes through a feature branch and pull request; merge only with explicit user authorization. English is the project writing language; it does not change the implementation stack or require English responses to a user writing in another language.

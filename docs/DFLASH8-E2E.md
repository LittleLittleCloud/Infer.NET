# DFlash2 eight-row end-to-end experiment

Approved experiment [#98](https://github.com/LittleLittleCloud/Infer.NET/issues/98) starts from main `4f51f241e87999c8cc3f79d733cd95ade9c711cd`. It is an opt-in candidate, not an adopted baseline. No timing result is claimed by this implementation document.

## Dependency audit

The main product sources have no changes between common ancestor `4ca29eed1a2acb8a870d33e980dce37dfbc1b7e3` and the fixed main baseline. Reused files are explicitly selected, without merging experiment branches:

- From unadopted #80, `c706064676ad5ad263ab23f146c285726167aa35`: `gpu_dflash.mm`, `Dflash2Device.cs`, `Dflash2Weights.cs`, `Dflash2Engine.cs`, adapters/host selector and focused tests; the necessary SafeTensors range reader, target tap hooks, exact-verifier and snapshot diagnostic interfaces. The draft loader preserves the pinned BF16 checkpoint; no MTP model, engine or host selector is imported. Existing common snapshot/exact-verifier primitives have historical #76 ancestry already documented in `DFLASH2.md`.
- From unadopted #95, `54a6ac3e9428fe15978e1ad6991c4a692487ef13`: target-block native/managed API, pending-state guards, independent state checks and diagnostic driver. Its measured product source was `cda86c0dfc16b5e98484b74e4b72d5345132dd98`.
- Conflict resolution combines separate block/exact pipeline selectors and graph lifetimes. New selected-layer taps stay on the GPU for both scalar and block execution. Native commit limits tap visibility to the selected prefix; draft ingest rejects pending/faulted blocks. Scalar verification captures each row's taps directly into its own device-buffer row.

The six-layer draft equations, shared target embedding/head and trained selector are implemented in this repository's C#/Metal. No external serving engine or Splash source is imported. Historical draft numerical failures are not erased by reuse. The newly captured native embedding checkpoint adds an independent value comparison, rather than the earlier shape-only assertion.

## Execution contract

The real cycle produces an anchor plus seven proposals, verifies those exact tokens, finds the matching prefix and emits the target correction/bonus as the next anchor. The native target remains tentative until `CommitPrefix`; every accepted prefix, including all-eight, is committed. Only published taps update the draft cache. The scalar reference ingests its known selected taps before rollback can overwrite them. Tail output slots are generated by original scalar forwards in both new modes. Block-ready output tokens share one measured timestamp; no intra-block token spacing is invented.

`native` and `scalar` are explicit `--dflash2-replay` modes. See [DFLASH2.md](DFLASH2.md) for pins and required host options. The combined draft-enabled window is 36864 to accommodate the approved 32768+4096 stress shape; Pi still uses its fixed 32768 context. RoPE tables already cover that long control. Default-off keeps the original model and context policies.

## Reproduction tools

Build `tools/Dflash8Bench` explicitly. Run only under an exclusive GPU maintenance window, using the fixed target/draft files and a fresh result directory:

```sh
DEEPINFER_METAL_KV=fp32 DEEPINFER_METAL_PREFILL_CHUNK=32 \
DEEPINFER_METAL_PREFILL_GEMM=fp32 DEEPINFER_METAL_PREFILL_MATRIX=0 \
DEEPINFER_METAL_PREFILL_DELTA=sequential \
DOTNET_GCHeapHardLimit=0x40000000 \
dotnet tools/Dflash8Bench/bin/Release/net10.0/Dflash8Bench.dll \
  gate TARGET_DIRECTORY DRAFT_DIRECTORY OUTPUT_DIRECTORY native
```

`request TARGET DRAFT OUTPUT off|scalar|native INPUT_TOKENS OUTPUT_TOKENS` executes one full prefill/generation request, saves exact token IDs, per-block readiness, prefill/decode/request wall clocks, speculation counters and allocation evidence. An external controller owns warmup/formal identities, counterbalanced order, input/version hashes, token equality, system swap brackets and service restoration. This single-request tool alone cannot establish a complete A/B experiment.

The gate checks every forced prefix, per-row device taps, all target KV/Delta/convolution state and real draft generation across tail/output boundaries. CPU state-machine tests cover every rejection offset, EOS at accepted/correction positions and no tentative ingest/replay. Independent draft/head/embedding GPU facts remain explicitly opt-in; skipped facts are not passes. Full qualification still depends on the approved numerical/resource gates and complete HumanEval/worker records. A known draft-only failure permits diagnostic measurements under #98, never an adoption recommendation.

## End-to-end clocks and transport diagnostics

`INFERENCE_METRIC` records terminal worker clocks for completed, failed and cancelled requests. Its output count describes generated tokens ready at the worker, including a complete ready block when transport subsequently fails; it is not the delivered-token count. Prefill cancelled before completion has a missing clock. Decode uses the first-to-last readiness interval and N−1 intervals; all tokens in a verified block share a timestamp. The worker record does not measure client TTFT.

`scripts/observe-dflash-e2e.py` extends the Issue84 loopback collector from source `349400b92b9de5efb88d73ce8cf5931f94f9e7b7` (upstream script SHA-256 `ad507a7f3cc40c87029ea96fc85c46c3b2cf77360de08ea6cbb753780e9e365d`). The same two observation hops are used for each arm. It records native token receipt times, compatible text/tool TTFT, exact worker output-token hashes and explicit API errors without saving prompt/output text. Client receipt times and worker timings remain separate; cancelled baseline requests without terminal worker timings are reported as missing, never inferred from dashboard values or successful requests.

A controlled fake-worker regression independently reproduces an uncaught malformed-tool-call exception. The compatibility layer now returns an explicit model-output API error. Malformed calls remain failures; this fix does not establish that every historical truncated stream had the same cause. This independently tested transport change is separate from the native target-block implementation and disclosed in the candidate-off comparison.

`fixture TARGET_DIRECTORY PROMPT_FILE OUTPUT_DIRECTORY` tokenizes a held-out text using the real CPU tokenizer, records exact counts and hashes, and exits before creating a Metal session. It does not load model weights or run a timing trial.

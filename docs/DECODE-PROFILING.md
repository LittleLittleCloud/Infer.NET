# Metal decode stage profiling

Candidate diagnostic implementation for [experiment #70](https://github.com/LittleLittleCloud/Infer.NET/issues/70), resumed by the user on 2026-10-25. Baseline: `4f51f241e87999c8cc3f79d733cd95ade9c711cd`. No arithmetic, precision, scheduling policy or deployment default changes.

Set `DEEPINFER_METAL_GPU_PROFILE=1` before starting an isolated worker to collect per-region timestamp counters plus host timing. Prefer dispatch boundaries when supported; otherwise use timestamp attachments on compute encoder boundaries. The observed M5 supports encoder boundaries and rejects dispatch boundaries. Encoder mode groups whole projection, Delta, attention, MoE and classifier phases and closes/reopens encoders before their bindings. Set only `DEEPINFER_METAL_DECODE_TIMING=1` for host/command timing without per-region counters. Both are disabled by default. Samples cover the first eight classifier forwards after reset and subsequent positions divisible by 128. Native prefill is not profiled by these records. The first generated token is normally produced by prefill; classifier forwards represent subsequent output tokens. Reset ordinals and token positions identify samples; they are not RPC request IDs.

Each `DECODE_STAGE_PROFILE` JSON record contains encode/commit/wait durations, command GPU duration, native readiness duration before diagnostic logging, named stage nanoseconds, region validity and dispatch coverage. Host wait includes GPU execution and scheduling; it must not be added to GPU time. Native readiness includes counter resolution and excludes record emission, managed token processing and client transport. These records do not measure client-visible token emission or TTFT.

Dispatch counter samples use barriers; encoder-boundary mode splits encoding into coarse regions. Both can serialize otherwise concurrent work and change submission overhead. Encoder-mode MoE is one complete block including routing, shared/routed experts, merge and next norm; dense projections are outside it. Non-overlapping regions cover dispatches; a fused attention region includes both attention dispatches and their internal synchronization. Some existing regions include a following buffer barrier. Stage times are therefore instrumented region costs, not isolated kernel compute or unperturbed utilization. Report stage sum, command duration, remainder and perturbation separately. Do not interpret the remainder as barrier cost or wall-minus-GPU as CPU optimization headroom. Reject missing, invalid or overlapping coverage instead of inventing shares.

`scripts/profile-qwen36-decode.py` collects one warm-up and three formal fixed requests against an already isolated authenticated loopback worker. It verifies input/output lengths, local topology, repeated token hashes, AC power, allocation and per-request swap gates, saving raw responses/log slices locally. The experiment controller must separately verify executable/native hashes, service identity and restoration, configuration, thermal state, memory pressure and process footprint. The driver does not manage services or silently change precision. Only one model may occupy the device during measurement.

Run the same frozen inputs on uninstrumented main, candidate default-off, and candidate profile-on. Preserve all valid slow trials and failures. The fixed pilot5 can diagnose application workload coverage; formal20 and the other registered checks remain required before adopting this diagnostic code. Long-context capacity must pass preflight before requests run. No performance result or adoption claim is supplied by this document.

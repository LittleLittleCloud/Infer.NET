## Deliverables

- TUI defaults to connecting to the local coordinator 5200; starts without parameters, reading existing repository deployment configurations. Compact borderless layout; real streaming multi-turn conversation driven by Microsoft.Extensions.AI.IChatClient, with Enter to send, Stop, new session, system/output settings, and history browsing.
- HTTP `/v1/chat/completions`, `/v1/messages`, `/v1/responses` all support non-streaming and SSE; `/v1/models` lists available models. Bearer and x-api-key are compatible with existing cluster tokens.
- Role-based history is fed into the Qwen template; multi-turn content is not flattened into a single user prompt. Cancelled/failed TUI turns retain screen content but do not add to subsequent history.
- Responses support full history return, including output items generated by this interface; response is not stored, and previous_response_id is not supported.
- Text, usage, stop reason, and error semantics in three formats are mapped separately; stream interruption does not send a successful completion marker, nor does it automatically replay partial outputs.

The current model is still Qwen3.6-35B-A3B affine 8bit/group64, revision `e06a74e6236a60c8367e1a3214e83d8b61b637b0`. Mac M5 Pro 48 GiB + Windows RTX 4090 24 GiB, via existing home LAN; custom Metal/CUDA paths, FP32 KV, input plus output up to 2048 tokens, output up to 256 tokens, prefill recalculated per turn, no prefix cache. The interface is compatible with a text subset; tools, images, JSON schema, custom stops, and non-greedy sampling explicitly return errors.

## Issues Found and Fixed

- Repeatedly writing response headers after the first SSE event caused stream failure; changed to set headers only when the response has not yet started, adding checks for three-format termination and truncation.
- RazorConsole 0.6 input component retained old buffers after sending, causing old text prefixes in multiple rounds; rebuilt the input component per round and verified the second-round request body. Used a plain text component to avoid repeated escaping of square brackets.
- The Responses SDK returned empty logprobs when passing back this interface's output; allowed empty/null metadata, but still rejected non-empty, and verified the true output → input round-trip.
- The first-round real SDK acceptance immediately called Messages stream after a short EOS and got 503; the next TLS connection on CUDA was not yet ready. The final version waits up to 5 seconds within a limited queue, returning 503 if the connection is missing; it does not start GPU work or retry inference. After the fix, two rounds of complete 15 real SDK tests passed, including continuous short requests. Failure records are retained locally in `artifacts/chat/real-chat.log`.

## Reproduction

Run the TUI from the repository root:

```sh
dotnet run --project src/DeepInfer.Tui -c Release
```

After installing openai and anthropic in an independent Python test environment, connect to the ready real deployment:

```sh
python scripts/chat-acceptance.py --token-file /PRIVATE/mac/token.txt --output artifacts/chat/real-UNIQUE
```

The original real deployment tests still use `scripts/deploy/acceptance.py`. Controlled protocol/SDK/terminal checks use `scripts/chat-integration.py --sdk --tui`, additionally requiring pexpect and pyte; these packages are for testing only, not product dependencies.

## Deployment Status and Boundaries

Mac coordinator/serve uses user LaunchAgents; Windows agents run in the foreground from the new version directory, maintained by retained SSH control sessions. **No Windows SCM service was created or claimed.** Old version directories, configurations, and startup definitions have been backed up.

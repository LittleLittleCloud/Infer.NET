# Full Projection 20 Layer BF16 Compensation and KV Accuracy Diagnosis, 2026-10-23

In the default-off diagnostic switch of [PR #31](https://github.com/LittleLittleCloud/Infer.NET/pull/31), 4090's QKV, output, and expert projections each use three BF16 Tensor Core products to compensate for high and low bits, with FP32 accumulation; weights remain fixed at affine8/group64. Fixed 128 synthetic tokens, 20 layers in the front segment, and diagnostic FP32 router/shared. Source code `a20449e1e818af5760076a83f822f5bceec07967`, SM89 DLL SHA-256 `5d383567f4e63dc39b61fb040e1aca369c6156224dd8b6b0e028ed99474c4b54`. Independent numerical reference uses a per-token MLX FP32 implementation with the same quantized weights; MLX **is not involved in production inference**. Metal FP32 device comparison comes from an earlier `1f42e6f`, so it cannot be written as a formal dual-machine acceptance test with the complete source code.

For the FP32 KV checkpoint, the relative independent reference for the first 20 layers is all below the fixed `1e-4` threshold, and the maximum absolute error also passes; the expert **set** in 2560 secondary token/layer decisions remains unchanged. The BF16 KV checkpoint and its FP32 GEMM internal comparison both fail starting from the 3 layer, i.e., the first complete attention layer: the relative L2 for this layer is approximately `4.0836e-4` and `4.0859e-4` respectively. This supports the hypothesis that KV storage/read rounding is the currently most prominent remaining discrepancy, but subsequent errors will accumulate, so not all posterior layer deviations can be attributed solely to KV.

The target requirement is BF16 KV, so **correctness has not yet passed in this round, and the FP32 KV results cannot be counted as compliant**. The latency of reading back dense isolated probes does not represent formal throughput; independent KV/state references, Mac backend, logits, greedy tokens, real RPC, 128K, VRAM, and performance thresholds have not yet been verified. The next step is to isolate the BF16 KV rounding of the first attention layer, find corrections that do not break the target memory budget, and then perform end-to-end tests with complete source code on both ends.
